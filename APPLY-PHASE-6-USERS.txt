===============================================

  git add -A ; git commit -m "Before Phase 6 users"

  routes/web.php:   use App\Http\Controllers\Admin\UserController;  +  ang group na Route::prefix('admin/users')
  navigation:       ang "Users" link (manage_users) at ang manage_users sa kondisyon ng "Administration"

Paano gumagana
  - Sidebar > Administration > Users (/admin/users). Capability: manage_users (maintenance_admin lang). Iba = 403, guest = login.
  - Listahan + search (pangalan, email, employee no.) + filter (role, department, status), 15 kada page.
  - Add user: pangalan, school email, role, department, employee no. May kusang TEMPORARY password
    (12 characters). Ipinapakita ISANG BESES lang sa admin. Pag-login ng user, diretso sa "Choose a new password".
  - Activate / Deactivate: ang inactive ay hindi na makaka-login at natatanggal ang open sessions niya.
  - Reset password: bagong temporary password, kailangang palitan sa susunod na login.
  - Edit: palit ng role at department.
  - HINDI puwede sa sarili: i-deactivate, palitan ang role, i-reset ang password (gamitin ang Profile).
    Kaya laging may natitirang active admin; hindi mai-lock out ang sistema.
  - AUDIT: user_created, user_updated (department), role_changed, user_deactivated, user_reactivated
    (galing sa UserObserver) at user_password_reset (bago). Hindi kailanman nasusulat ang password sa audit log.

Dagdag na pagbabago (kailangan para gumana ang Deactivate)
  - LoginRequest: Auth::attempt na ngayon ay may 'is_active' => true. Dati, nakakapag-login pa ang inactive.

Rollback: git checkout -- . ; at burahin ang 3 bagong file.
